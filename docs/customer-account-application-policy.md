# 고객 계좌 개설 정책

- 고객 최초 신청은 기존 한도 입력 검증·업무시계·마이데이터 한도 계산을 재사용한다.
- 고객 경로는 신청 기간 밖, 설정 가능 한도 0원, 설정 가능 한도 초과를 저장 전에 거부한다. 거부된 신청은 계좌·상태·혜택·감사로그를 생성하지 않는다.
- 조건을 만족한 고객 최초 신청은 기존 자동 개설 트랜잭션을 사용한다. 관리자 대리 신청의 기존 심사 대기 정책은 유지한다.
- 고객 신청과 자동 개설은 `audit_log.actor_type=CUSTOMER`, `actor_id=customer_id`, `admin_id=NULL`로 기록한다. 기존 DDL에 정의된 컬럼만 사용한다.
- 계좌 생성, 상태·혜택 이력과 감사로그를 같은 트랜잭션에서 기록한다. 감사로그 저장 실패 시 전체 변경을 롤백한다.
- 관리자 신청은 명시적인 ADMIN actor와 관리자 ID를 요구한다. 누락된 관리자 ID를 고객 행위나 감사 생략으로 해석하지 않는다.
- 기존 감사로그 호출자의 `admin_id` 입력도 보존하며 actor가 없는 기존 호출은 ADMIN으로 저장한다.
- 거절·해지 후 고객 재신청은 이번 최초 개설 API에 포함하지 않는다. 기존 관리자 재신청 절차를 유지한다.
- 다른 증권사의 한도는 외부 API 응답 시점 기준이며, 다른 시스템 DB를 잠그거나 직접 조회하지 않는다.

고객 웹은 서버의 409 응답을 받으면 재제출 버튼을 제거하고 본인 계좌·신청 상태 확인을 안내한다.
